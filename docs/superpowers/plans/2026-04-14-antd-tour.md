# Ant Design Tour Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a dev-only guided tour using Ant Design's `<Tour>` component that auto-navigates between all pages, highlighting key features with interactive demos.

**Architecture:** A `TourContext` provides a ref registry and action callbacks shared across all pages. A `DemoTour` component orchestrates step transitions with page navigation (via `setNavigationValue` + `pushState`), polling for lazy-loaded target refs, and running interactive actions. Each page registers wrapper `<div>` refs via a `useTourRef` hook.

**Tech Stack:** React 18, Ant Design 5.20+ (built-in Tour component), Meteor.js 3.4+

**Spec:** `docs/superpowers/specs/2026-04-14-antd-tour-design.md`

## Chunk 1: Core Infrastructure

### Task 1: TourContext — Context, Provider, and Hooks

**Files:**
- Create: `imports/ui/tour/TourContext.jsx`

This is the foundation. The context holds a ref registry (for Tour targeting), an action registry (for interactive step callbacks), and tour state (open/step). The `useTourRef` hook lets any page register a DOM ref. The `useTourAction` hook lets pages register callable actions.

- [ ] **Step 1: Create `imports/ui/tour/TourContext.jsx`**

```javascript
import React, { createContext, useCallback, useContext, useEffect, useMemo, useRef, useState } from 'react';
import PropTypes from 'prop-types';

const TourContext = createContext({});

export function TourProvider({ children }) {
  const refsMap = useRef({});
  const actionsMap = useRef({});
  const [open, setOpen] = useState(false);
  const [currentStep, setCurrentStep] = useState(0);

  const registerRef = useCallback((key, ref) => {
    refsMap.current[key] = ref;
  }, []);

  const unregisterRef = useCallback(key => {
    delete refsMap.current[key];
  }, []);

  const registerAction = useCallback((key, fn) => {
    actionsMap.current[key] = fn;
  }, []);

  const unregisterAction = useCallback(key => {
    delete actionsMap.current[key];
  }, []);

  const startTour = useCallback(() => {
    setCurrentStep(0);
    setOpen(true);
  }, []);

  const stopTour = useCallback(() => {
    setOpen(false);
    setCurrentStep(0);
  }, []);

  const value = useMemo(
    () => ({
      refs: refsMap,
      actions: actionsMap,
      open,
      currentStep,
      registerRef,
      unregisterRef,
      registerAction,
      unregisterAction,
      setOpen,
      setCurrentStep,
      startTour,
      stopTour,
    }),
    [open, currentStep, registerRef, unregisterRef, registerAction, unregisterAction, startTour, stopTour]
  );

  return <TourContext.Provider value={value}>{children}</TourContext.Provider>;
}
TourProvider.propTypes = {
  children: PropTypes.node.isRequired,
};

export function useTourRef(key) {
  const ref = useRef(null);
  const { registerRef, unregisterRef } = useContext(TourContext);

  useEffect(() => {
    registerRef(key, ref);
    return () => unregisterRef(key);
  }, [key, registerRef, unregisterRef]);

  return ref;
}

export function useTourAction(key, fn) {
  const { registerAction, unregisterAction } = useContext(TourContext);
  const fnRef = useRef(fn);
  fnRef.current = fn;

  useEffect(() => {
    registerAction(key, (...args) => fnRef.current(...args));
    return () => unregisterAction(key);
  }, [key, registerAction, unregisterAction]);
}

export default TourContext;
```

## Chunk 2: Tour Component and App Integration

### Task 4: DemoTour Component

**Files:**
- Create: `imports/ui/tour/DemoTour.jsx`

This component renders `<Tour>` from antd with controlled `current`/`open` props. It intercepts `onChange` to orchestrate:
1. Page navigation via `setNavigationValue` + `pushState`
2. Polling for target ref (50ms interval, 3s timeout) to handle lazy-loaded pages
3. Running step actions (DOM clicks, registered callbacks)
4. Running previous step cleanup

The Tour is closed during page transitions to avoid dangling popovers. It reopens once the target ref appears.

**Important context:**
- `useNavigation()` hook from `imports/ui/navigation/navigation.hook.jsx` provides `{ navigationValue, setNavigationValue }`
- `useTranslation()` from `imports/i18n/LanguageContext` provides `{ t }`
- The dev-only guard lives in App.jsx (conditional rendering), NOT inside DemoTour — this avoids violating React's Rules of Hooks
- Navigation pattern: `setNavigationValue(page)` updates React state, `window.history.pushState(null, null, '/' + page)` updates the URL
- When `step.page` is `null`, the target is always visible (header elements) — skip navigation

- [ ] **Step 1: Create `imports/ui/tour/DemoTour.jsx`**

```javascript
import { Tour } from 'antd';
import { Meteor } from 'meteor/meteor';
import React, { useCallback, useContext, useMemo, useRef } from 'react';
import { useTranslation } from '../../i18n/LanguageContext';
import useNavigation from '../navigation/navigation.hook';
import TourContext from './TourContext';
import getTourSteps from './tourSteps';

function pollForElement(targetFn, timeoutMs = 3000, intervalMs = 50) {
  return new Promise(resolve => {
    const start = Date.now();
    const check = () => {
      const el = targetFn();
      if (el) return resolve(el);
      if (Date.now() - start >= timeoutMs) return resolve(null);
      setTimeout(check, intervalMs);
    };
    check();
  });
}

export default function DemoTour() {
  const { refs, actions, open, currentStep, setOpen, setCurrentStep, stopTour } = useContext(TourContext);
  const { navigationValue, setNavigationValue } = useNavigation();
  const { t } = useTranslation();
  const transitioning = useRef(false);

  const steps = useMemo(() => getTourSteps(t, refs, actions), [t, refs, actions]);

  const navigate = useCallback(
    page => {
      setNavigationValue(page);
      window.history.pushState(null, null, `${window.location.origin}/${page}`);
    },
    [setNavigationValue]
  );

  const handleChange = useCallback(
    async nextStep => {
      if (transitioning.current) return;
      if (nextStep < 0 || nextStep >= steps.length) return;
      transitioning.current = true;

      try {
        const prevStep = steps[currentStep];
        const step = steps[nextStep];
        const needsNavigation = step.page !== null && step.page !== navigationValue;

        // Run cleanup on previous step
        if (prevStep?.cleanup) {
          prevStep.cleanup(actions);
        }

        // Navigate if needed
        if (needsNavigation) {
          setOpen(false);
          navigate(step.page);
        }

        // Run action if defined
        if (step.action) {
          // Brief delay for page mount after navigation
          if (needsNavigation) {
            await new Promise(r => setTimeout(r, 300));
          }
          await step.action(actions);
        }

        // Poll for target element
        if (step.target) {
          await pollForElement(step.target, 3000, 50);
        }

        setCurrentStep(nextStep);
        setOpen(true);
      } finally {
        transitioning.current = false;
      }
    },
    [steps, currentStep, navigationValue, navigate, setOpen, setCurrentStep, actions]
  );

  const handleClose = useCallback(() => {
    const prevStep = steps[currentStep];
    if (prevStep?.cleanup) {
      prevStep.cleanup(actions);
    }
    stopTour();
  }, [steps, currentStep, actions, stopTour]);

  if (!open) return null;

  return <Tour open={open} current={currentStep} onChange={handleChange} onClose={handleClose} steps={steps} />;
}
```

## Spec Divergences

The following spec details were adapted during planning based on actual codebase analysis:

1. **Tasks kanban switching (Step 11):** Spec calls for clicking a "Kanban toggle button" with ref key `tasks-kanban`, but no such button exists — the view type is stored in `Meteor.user().profile.taskFilter.type` and set through a filter drawer (requires a Meteor method call). The step targets `tasks-section` (the whole Tasks page) without switching views. The `KanbanBoard.jsx` does NOT get a tour ref since no step targets it. If kanban demo is needed, the presenter can manually set the filter before the tour.

2. **Events view switching:** Spec calls for `document.querySelector('[data-tour="events-calendar-tab"]')?.click()` but the view is controlled by an antd `<Select>` which doesn't expose clickable DOM elements for individual options. Instead, uses `useTourAction` callbacks registered in Events.jsx that call `handleViewTypeChange()` directly — simpler and more reliable. No `data-tour` attributes are added to Events.jsx.

3. **Events attendance (Step 10):** Spec says "Open attendance for an event" by clicking `[data-tour="event-attendance-btn"]` on a row. The actual UI shows attendance as a view type in the Select dropdown, not a per-event button. The step switches to the attendance view type via a `useTourAction` callback instead.
